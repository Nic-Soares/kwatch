# T15 · Laço do menu, sair e opção inválida (PDF p12, p16)

Onde houver □, a resposta ainda falta. Responda antes de escrever no `main.c`.

## 0. Definição

Com as suas palavras, em 1 ou 2 frases: o que o laço do menu faz e quando ele termina.
Consulte: [Menu e segundos menus](referencia.md#menu-e-segundos-menus) e o [conceito 38](../conceitos.md#38-menu-com-do-while-e-switch).

Minha definição: O laço do menu mostra as opções, lê a escolha do usuário e executa a opção (ou avisa que é inválida), depois repete. Ele termina quando o usuário digita 6, que mostra Encerrando o programa.

## 1. O que cada opção faz nesta tarefa

Nesta tarefa as opções 1 a 5 ainda não fazem nada (cada uma é uma tarefa, T16 a T20); o menu só precisa voltar. A 1ª linha é o modelo.
Consulte: [Menu e segundos menus](referencia.md#menu-e-segundos-menus) e o caso 5 de `tests/casos.md`.

| Opção digitada | O que aparece | O menu volta? |
|---|---|---|
| 1 a 5 | (nada, por enquanto) | sim |
| 6 | Encerrando o programa. | não |
| 9 | Opcao invalida. Tente novamente. | sim |
| 0 | Opcao invalida. Tente novamente. | sim |

## 2. Por que `do`/`while`

O menu aparece **pelo menos uma vez**, antes de ler qualquer opção. Por que o `do { ... } while (opcao != 6);` serve melhor que um `while (opcao != 6) { ... }`? Pense no valor de `opcao` antes do primeiro `scanf`.
Consulte: o [conceito 38](../conceitos.md#38-menu-com-do-while-e-switch), tabela.

Antes do primeiro scanf, opcao ainda não tem um valor lido. Com while (opcao != 6) { ... }, a condição seria testada antes de qualquer leitura, com um valor sem sentido. Se a variável começasse como 6, o corpo nunca rodaria e o menu não apareceria. Com do { ... } while (opcao != 6);, o corpo roda primeiro: o menu aparece, o scanf lê a opção, e só então a condição é testada.
